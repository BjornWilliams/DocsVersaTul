Support And Feedback
====================

Use the route that matches your request. Public GitHub issues are visible to
everyone. Do not post private application data, credentials, or vulnerability
details there.

.. list-table:: VersaTul support routes
   :header-rows: 1

   * - Request
     - Route
     - What to include
   * - Bug report
     - `Open a public bug report <https://github.com/BjornWilliams/DocsVersaTul/issues/new/choose>`_
     - Affected package and version, target framework, expected and actual result, and a minimal reproduction without secrets.
   * - Usage question
     - `Ask a public usage question <https://github.com/BjornWilliams/DocsVersaTul/issues/new/choose>`_
     - Package and version, relevant code/configuration with secrets removed, and the result you expected.
   * - Feature proposal
     - `Propose a feature <https://github.com/BjornWilliams/DocsVersaTul/issues/new/choose>`_
     - User problem, the desired outcome, and any compatibility constraints.
   * - Security disclosure
     - See :doc:`security` for private disclosure guidance.
     - Do not use a public issue. Ask the NuGet package owner for a private channel if GitHub private reporting is unavailable.

The issue tracker is a public feedback channel, not a support contract. No
response-time or service-level commitment is published. For package status,
see :doc:`compatibility` and :doc:`release-notes`.
