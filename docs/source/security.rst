Security Policy
===============

Do not report suspected vulnerabilities in a public issue, discussion, pull
request, or commit. Those routes are visible to everyone and are intended for
ordinary defects, usage questions, documentation help, and feature proposals.

If GitHub presents a private vulnerability report form for the repository, use
`Report a vulnerability privately <https://github.com/BjornWilliams/DocsVersaTul/security/advisories/new>`_.
If that form is unavailable, open the affected package page from the
:doc:`package-catalog` and use **Contact owners** only to request a private
disclosure channel. Do not include vulnerability details in that initial
request; share them after a maintainer confirms that the reply channel is
private. The repository-level instructions are in the public
`SECURITY.md <https://github.com/BjornWilliams/DocsVersaTul/blob/main/SECURITY.md>`_.

For a confirmed private channel, include the affected package and version,
target framework, impact, a minimal reproduction, and any known mitigation.
Do not include credentials or customer data.

The documentation repository is public, while the library source repository is
hosted separately in Azure Repos; access to that repository may require sign-in.
See :doc:`repository-access` for the current access statement.
