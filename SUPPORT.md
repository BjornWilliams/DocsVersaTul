# Support and feedback

Use the route that matches your request. Public issues are visible to everyone;
remove credentials, personal information, and private application data before
posting.

- **Bug report:** [Open a bug report](https://github.com/BjornWilliams/DocsVersaTul/issues/new?template=bug_report.yml).
- **Usage question:** [Ask a usage question](https://github.com/BjornWilliams/DocsVersaTul/issues/new?template=usage_question.yml).
- **Feature proposal:** [Propose a feature](https://github.com/BjornWilliams/DocsVersaTul/issues/new?template=feature_request.yml).
- **Documentation help:** [Request a documentation correction or explanation](https://github.com/BjornWilliams/DocsVersaTul/issues/new?template=documentation_help.yml).
- **Security concern:** follow [SECURITY.md](SECURITY.md). Never post vulnerability details in a public issue, discussion, or pull request.

For a useful bug report, identify the affected package and version, target
framework, actual and expected behavior, reproduction steps, and the smallest
useful example. Remove credentials, customer records, and unrelated private
application data. For a feature proposal, describe the user problem and desired
outcome; a proposed API is optional. For documentation help, include the page
URL, what you were trying to do, and what is unclear or incorrect.

The public issue tracker is maintained by the DocsVersaTul repository owner and
is a feedback channel, not a support contract. The VersaTul source repository
is hosted separately in Azure Repos and may require sign-in; see the [public
documentation](https://docsversatul.readthedocs.io/en/latest/repository-access.html)
for access information. The [support guide](https://docsversatul.readthedocs.io/en/latest/support.html)
lists routes and privacy expectations; the [code of conduct](CODE_OF_CONDUCT.md)
explains expectations and how to request a private channel for conduct concerns.
